# アニたび (Anime Pilgrimage)

アニメの「聖地巡礼」をサポートし、ファンの「行きたい」という動機を実際の行動に変えるためのWebアプリケーションです。
GPSを用いたスタンプラリー機能や、OpenAI APIを活用した旅行プラン提案機能などを備えています。

## 🎯 プロジェクトの目的と背景
大学のチーム開発実習において、リードエンジニアとして企画・開発・インフラ構築を主導したプロジェクトです。
「チーム全体の生産性最大化」をテーマに、Gitによる分散開発フローの策定、Dockerを用いた開発環境の標準化、およびAWS EC2へのデプロイメント環境の構築を行いました。

## 🛠 技術スタック

### インフラ・開発環境
- **インフラストラクチャ:** AWS (EC2 / Ubuntu)
- **コンテナ化:** Docker, Docker Compose
- **バージョン管理:** Git, GitHub

### バックエンド・データベース
- **フレームワーク:** Python, Django 5.x
- **データベース:** PostgreSQL

### 外部API・サービス
- **画像ホスティング:** Cloudinary
- **AI連携:** OpenAI API (旅行提案機能)
- **位置情報:** GPS連携

## 🏗 インフラ構成と工夫した点

インフラ担当として、以下の環境整備と課題解決に注力しました。

1. **Dockerによる環境のコンテナ化**
   - 複数人のチーム開発において「環境への依存」をなくすため、`Dockerfile`および`docker-compose.yml`を記述し、コマンド1つでDB（PostgreSQL）を含む全環境が立ち上がる構成にしました。
2. **AWS (EC2) 本番環境の構築とネットワーク設定**
   - 開発したアプリをAWS EC2(Ubuntu)上にデプロイしました。
   - セキュリティグループのポート設定と特定ネットワーク（大学内Wi-Fiなど）の相性による接続障害に対し、Web標準のポート（80番）へのルーティングとファイアウォール設定の見直しを行い、可用性を向上させました。
3. **データベースのマイグレーションと内部完結化**
   - 当初は外部PaaS（Render）のデータベースを利用していましたが、運用コストと依存関係を見直し、AWS上のDockerコンテナ内（PostgreSQL）へデータマイグレーション（pg_dump/loaddata等を利用）を実施。インフラ環境の完全な内部完結とデータ永続化（Docker Volume）を実現しました。
4. **クラウドストレージの活用**
   - 画像等の静的メディアファイルはサーバーのストレージを圧迫しないよう、Cloudinaryと連携させて効率的に管理する設計としています。

## 🚀 ローカル環境の構築手順 (Setup)

Dockerがインストールされている環境であれば、以下の手順で環境を構築できます。

```bash
# 1. リポジトリのクローン
git clone [https://github.com/s1F10230095/anime_pilgrimage.git](https://github.com/s1F10230095/anime_pilgrimage.git)
cd anime_pilgrimage

# 2. 環境変数ファイル(.env)の作成
# プロジェクトルートに .env を作成し、各種APIキーやDB設定を記述します。
touch .env

# 3. Dockerコンテナのビルドと起動
docker compose up -d --build

# 4. データベースのマイグレーション
docker compose exec web python manage.py migrate
